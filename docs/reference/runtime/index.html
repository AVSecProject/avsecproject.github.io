    Runtime reference¶

    Audience: Adapter and attack implementers.

    Outcome: Look up decision order, stages, contexts and recorded evidence.

    Prerequisites: Architecture.

    Initialization¶

    The caller creates SimulatorRuntime and AVStack. The runner validates hook stages, environments and command compatibility before reset. The simulator prepares the selected origin using the shared deployment tick budget, applies setup actions and captures the initial observation. Simulator-specific origin and capture behavior is described in Simulators.

    AttackRuntime.setup receives its subscribed state and returns zero or more WorldAttackAction values. Actions register cleanup on the supplied ExitStack. See budget rules in Writing attacks.

    Driving-history acquisition follows Past observations. The initialization event records past_captures and each historical observation's t and vehicle_state without sensor images.

    One decision¶

    Simulation events use integer timestamps and priorities. At the same timestamp, frames precede localization, decisions and propagation. Computation finishes before virtual time advances. Scheduling and duration calculations use integer microseconds. NuRec and in-memory t values derive from that clock. CARLA preserves its native floating timestamps and recorded replay preserves dataset timestamps. Scheduling owns parameter names and defaults.

    Each sensor has an independent frame_interval_us clock. Frames end at the origin plus integer multiples of that interval. A frame event occurs at its end and applies sensor actions, sensor environments and sensors.post. Localization runs at decision timestamps and pose_reporting_interval_us timestamps, using any frames that end exactly there. A pose timestamp may have no frames. Frame state estimates interpolate between estimated poses.

    At a decision timestamp:

    1. Acquire frames ending exactly at that timestamp. The raw batch may be empty.
    2. Call AttackRuntime.step, apply same-frame actions and process the frame batch.
    3. Localize the decision pose after sensors.post.
    4. Transfer all newly ended frames and pose estimates, then apply observation hooks.
    5. Reset the stack on its first input, then request a command unless driving is skipped.
    6. Apply command hooks and add the controller reference to the planner_delay_us buffer.
    7. Select the buffered reference and propagate one control interval.

    Intermediate pose events run localization without driving inference. Sensor clocks do not determine the controller's integration or intermediate reporting times.

    flowchart LR
    F[Frame clocks] --> S[Sensor actions and sensors.post]
    P[Pose reports] --> L[Localization]
    S --> B[New frames]
    L --> B
    B --> D[Decision input hooks and AV stack]
    D --> Q[planner_delay_us buffer]
    Q --> C[Controller and force_gt]
    C --> F
    C --> P

    Feedback (after_step and step.end) uses the next decision timestamp's raw batch, containing only frames ending exactly then. It may contain no sensor payloads. The terminal boundary has physical state and any due raw frames but performs no further attack step, localization or driving inference.

    SimulatorRuntime.configure_timing sets clocks before reset. advance_interval propagates one control interval and reports poses on pose_reporting_interval_us. capture_at reads scheduled sensor frames using their interpolated physical start/end poses. It never adds integration steps. Read physical truth with state() after publishing a timestamp with capture_at. Read captured viewpoints with sensor_view(sensor).

    World actions returned by a decision apply at simulator.step.pre, before interval propagation. Their effects appear in later frames. InsertObject has zero setup ticks. Setup insertions are present in the first capture. Framework objects remain separate in WorldSnapshot.objects.

    Moving inserted objects¶

    MoveObject and SimulatorRuntime.move_object set the inserted object's pose at the end of the interval beginning at simulator.step.pre. Within the interval, translation is linear and rotation uses spherical interpolation. In an interval without a move, the object stays in place.

    At a movement endpoint, the recorded velocity is the velocity of the segment that arrived there. Within a segment, velocity is its displacement divided by its duration. After the last node, it is zero. At insertion and earlier, the velocity is the world-frame vector supplied to InsertObject or insert_object, which defaults to zero.

    An object inserted during reset is anchored to the origin capture. Earlier frames use its insertion orientation and its position extrapolated backward from the origin with the initial velocity. Objects inserted during a run are absent from the recorded history preceding it.

    Offline rendering has no decision interval. Supply the object's pose for each requested frame with InsertObject.

    Delivery and coordinates¶

    Observation.t, vehicle_state, ego_speed and route describe the decision timestamp. deliveries[sensor_id] contains this decision's newly ended frames, oldest first. Each DeliveredAcquisition records its frame interval, native frame, payload, calibration, capture ID and interpolated state estimate. sensor_data and calibration own the latest frame actually delivered in this decision. A dropped frame affects only itself. A sensor is absent if no frame for it was delivered. When every due frame of a sensor was dropped, deliveries[sensor_id] is an empty tuple, so drivers can tell a dropped sensor from one with no frame due.

    state_estimates contains new localization results through the decision timestamp, oldest first. Read frames through delivered(sensor_id) and poses through estimated_states(). The latest frame reads the current payload and calibration mappings. A frame at the decision's pose timestamp reads the current vehicle_state and ego_speed. Earlier estimates stay unchanged. Stripped payloads read as None. See the observation API for reading rules and errors.

    Convert measurements with their frame's pose, not the decision pose. Observation hooks may replace owner fields before inference. At a pose timestamp that also ends frames, localization.pre edits to payloads and calibration update those frames before delivery. Removing a model-input sensor raises an error when model-input recording selects its acquisition. Raw-only recording can retain a sensor removed from model input.

    AVStack.reset(observation) receives the first decision input. See Recorded input history for the complete HistoryRequirement contract. There is no separate history argument.

    Planner delay and recorded motion¶

    planner_delay_us uses AlpaSim's delay-buffer selection. Add each reference with its decision timestamp. Remove the oldest reference while a second reference is old enough for the delay, then return the oldest remaining reference. A sole reference is returned immediately, even before it has aged by the delay. Delay does not introduce a recorded-motion startup period. executed_command_issue_time_us identifies the selected reference's generation time.

    Trajectory coordinates retain their generation-time rig frame and timestamps. The controller resolves them against its ego trajectory. Actuator commands have no spatial frame.

    When both simulator and driving system declare no command modes, the driver returns None. This bypasses the delay buffer and records both produced and executed commands as None. CARLA native ROS 2 control records the server's applied control in telemetry.ego_control. Metrics requiring executed commands, including brake_steps, are unavailable. See native ROS 2 control.

    force_gt_duration_us configures recorded motion independently of planning delay. A decision is force_gt when its target timestamp belongs to the inclusive interval from the origin through the origin plus that duration.

    Trajectory simulators enqueue a recorded reference and track it during force_gt. StepRecord.executed_command records that reference. Actuator simulators enqueue the driver's command but replay recorded world motion, so their executed_command is None. Skipping the driver produces empty StepRecord.components and not_applied receipts for actions whose stages did not run.

    See NuRec recorded motion for reference trajectories and physics blending, scheduling constraints for driver skipping, driver ingestion for skipped inference, and evaluation for decision exclusions.

    Control visibility¶

    At a decision boundary, feedback for the preceding interval finishes before control is cleared. Input processing then sees control=None. Raw boundary rendering belongs to the preceding interval and sees its executed reference. After buffer selection, simulator step hooks, intermediate hooks and feedback see the actual controller reference. A zero-decision run processes the origin through sensor environments, capture, localization and observation hooks without attack step or sensor actions.

    Attack actions¶

    Action Boundary
    WorldAttackAction Simulated-world changes
    SensorAttackAction Sensor capture changes, including camera, LiDAR, GNSS and IMU
    AVStackAttackAction Driving-system values from localization.pre through command

    Sensor actions, including overlapping durations, chain in issue order on independent data. They preserve the raw capture and native calibration and acquisition metadata. Camera buffers use RGB uint8. SensorAttackAction.active_for_us=0 applies once to the issuing decision's capture. If its sensor has no frame ending then, the action receives not_applied with reason sensor_not_acquired_at_issue_time. It does not modify a cached frame or a later acquisition. A positive duration applies at every due capture in [issue_time, issue_time + duration). None lasts until the run ends. Each application has its own receipt. An action that expires or stops without encountering a due frame receives not_applied. No attack step is called at intermediate captures. AVStackAttackAction rejects sensors.post, which remains a normal hook stage. A requested AVStack stage not reached in that decision makes the decision fail. When some sensor had no frame due in that decision, the action instead receives not_applied with reason stage_not_executed. Action stages are checked when actions are issued. Hook stages and command modes are checked when each run starts.

    Sensor views¶

    SensorView.camera and cam_from_world describe optical geometry when available. Optical axes are x right, y down, z forward. sensor_from_world describes the sensor body axes: x forward, y left, z up. It is None when the sensor pose is unavailable. The two transforms are distinct for cameras. SimulatorRuntime.sensors lists all views. camera_sensors lists its camera subset. SensorView.objects contains the inserted objects associated with the capture.

    object_masks maps those same object IDs to boolean H×W masks of visible pixels in data. Each mask's pixel count equals the corresponding ObjectVisibility.visible_pixels. composition exists only for composite insertion. It describes how the framework composed objects into data, and composition.plan.apply(composition.background).image reproduces it. Other captures have composition=None. object_occlusion is geometry, rendered_probes or scene_render. Scene insertion uses occlusion_tolerance_m=0.0. See Simulators for insertion and visibility behavior.

    LiDAR data¶

    PointCloud stores a scan in the sensor coordinate frame at scan end. Its axes are x forward, y left and z up, with distances in meters. Observation.sensor_data stores the cloud and Observation.calibration stores its LidarCalibration under the same sensor name.

    Record Field Meaning
    PointCloud points Finite float32 array of shape (N, 3) in scan-end sensor coordinates
    PointCloud intensity Float32 array of shape (N,) in [0, 1], or None when unavailable
    LidarCalibration rig_from_lidar A 4×4 rigid transform from sensor coordinates to rig coordinates
    LidarCalibration spin_period_s Calibrated spin period in seconds, used to validate the NuRec capture schedule

    Both records can be saved in RunLog. Point and intensity arrays use payload shards. sensor_from_world in a LiDAR view uses the scan-end sensor pose.

    This action shifts a framework point cloud one meter forward without changing its intensity:

    from avsectester.attack.runtime import SensorAttackAction
from avsectester.data_types import PointCloud


class ShiftPointCloudAction(SensorAttackAction):
    sensor = "lidar_gt_top_p128"

    def apply(self, data, view):
        points = data.points.copy()
        points[:, 0] += 1.0
        intensity = None if data.intensity is None else data.intensity.copy()
        return PointCloud(points, intensity)

    Return it from AttackRuntime.step. The runner replaces the whole PointCloud payload.

    CARLA LiDAR data¶

    CARLA LiDAR keeps avstack's native format, which ModularAVStack passes to avstack unchanged.

    A CARLA LiDAR view contains an owned SensorCapture. raw_data holds packed float32 records x, y, z, intensity: four values, or 16 bytes, per point. These bytes use CARLA sensor axes: x forward, y right, z up. sensor_from_world uses the canonical body axes whose y points left.

    Replacing the capture retains the native LidarData wrapper and its flipy setting. With flipy=True, the native exporter negates y. Supply replacement points in the original CARLA axes and preserve the capture's frame, timestamp and metadata.

    This action shifts the points one meter forward:

    import numpy as np
from avsectester.attack.runtime import SensorAttackAction
from avsectester.closed_loop.simulators.carla.sensors import SensorCapture

class ShiftLidarPointsAction(SensorAttackAction):
    sensor = "lidar"

    def apply(self, data, view):
        points = np.frombuffer(data.raw_data, dtype=np.float32).reshape(-1, 4).copy()
        points[:, 0] += 1.0
        return SensorCapture(
            native_type=data.native_type,
            raw_bytes=points.tobytes(),
            frame=data.frame,
            timestamp=data.timestamp,
            metadata=dict(data.metadata),
        )

    Return it from AttackRuntime.step. The runner supplies its current capture and SensorView.

    Hook stages¶

    Hook(stage, handler) accepts a callable or an object with transform(value, context), where context is a StageContext. Handlers execute in registration order and consume preceding replacements. At sensors.post and localization.pre, sensor_data contains only sensors due at that time. A handler targeting one sensor should leave batches without that sensor unchanged. Adapters declare their supported stages. Unsupported stages fail before reset.

    Stage Value
    simulator.setup None, native world setup
    simulator.step.pre and simulator.step.post None, before propagation and when its endpoint is published
    sensors.post Observation containing only the sensors due at that acquisition time
    localization.pre Observation, present only with a configured localizer
    localization.post StateEstimate
    observation Observation of delivered inputs at a decision
    perception.pre and perception.post CallInputs or component output, when declared
    tracking.pre and tracking.post CallInputs or component output, when declared
    planning.pre and planning.post CallInputs or component output, when declared
    control.pre and control.post CallInputs or component output, when declared
    policy.pre and policy.post Policy inputs or output, when declared
    command Control before execution
    render.pre and render.post CameraPoseRequest or rendered sensor, when declared

    NuRec render.pre uses a 4×4 world_from_rig pose in CameraPoseRequest. The simulator.setup and simulator.step.* handlers return None. A component pre-hook returns CallInputs(args, kwargs). A post-hook returns the replacement output. NativeHook adapts an explicitly registered avstack-library hook.

    Contexts and lifecycle¶

    OnlineContext exposes step, stage, sim_time, frame, decision_time_us, decision_period_us and force_gt, with optional subscribed observation and physical_state snapshots. force_gt reports whether the decision follows recorded motion. The microsecond fields are set for decision callbacks. Setup and pre-run cleanup can leave them None. record_output writes named output during a run. The context carries no native runtime or time-advancing service. Bound AVStackAttackAction methods also receive the actual stage value.

    StageContext exposes step, stage, sensor, physical_state, observation, control, run resources, rng and record_output. simulator_runtime and avstack expose borrowed native resources. Using native SDK objects ties a handler to that simulator or driving system.

    Plugin.transform is required. reset(context), after_step(context) and close() are optional. after_step receives the next decision boundary's raw capture and clock. Intermediate render hooks receive that sensor's acquisition timestamp and viewpoint. Recorded-history acquisition bypasses render and input hooks. HookSet manages each handler owner's lifecycle once, including owners registered at several stages. Stateful handlers reset per run or are newly constructed. ObservationPipeline owns its localizer, whose lifecycle joins the other handlers.

    Randomness¶

    Sensor corruptions and hooks follow the randomness rules.

    Physical and model-visible records¶

    StateEstimate contains the model-visible vehicle_state and ego_speed produced by localization. Physical snapshots remain separate from these values.

    Record Fields and coordinates
    Observation t, frame, sensor_data, calibration, vehicle_state, ego_speed, route, deliveries, state_estimates. Model-visible
    Control throttle, steer, brake, optional trajectory
    WorldSnapshot t, frame, vehicle_state, ego_speed, ego, actors, traffic_lights, objects. Physical
    ActorState world-from-actor pose, velocity, category, optional extent, local box_center and box_rotation
    Detection ego-frame position, full extent, yaw, category, score
    RecordedOutput name, copied value, decision step, stage, physical frame and t, sensor

    ActorState.extent is full length, width and height in meters. None means unavailable. box_center is the actor-local box center. box_rotation is local roll/pitch/yaw in degrees. box_transform() combines these with the actor pose to return the world-from-box transform. Operations requiring dimensions report missing evidence when extent is None.

    Detection uses the true capture-time ego frame, independently of driving localization: x forward, y left, z up, and yaw in radians. None detections means unsupported. An empty sequence means supported with no detections. WorldSnapshot.traffic_lights maps map control IDs to red, yellow, green, off or unknown. Simulator support is described in Simulators.

    RunLog¶

    Registered dataclasses use JSON objects with _avsectester_type: "dataclass", type: "module:Class" and an encoded fields mapping. Mapping-key order is encoded separately. User mappings containing reserved serialization keys are escaped and round-trip unchanged. Payload retention defaults are defined in Configuration reference.

    StepRecord separates raw_observation from model_observation, physical_pre from physical_post, and produced_command from executed_command. It also stores components, detections, actions, outputs, sensor_geometry, object_visibility and telemetry. Physical records retain framework object state. executed_command_issue_time_us identifies the actual command's production time. force_gt marks decisions whose physical motion follows the recording. delivered_captures maps sensors to the capture IDs delivered in that decision. Driving systems record the frames they actually use in component_log. physical_captures maps sensors to their latest physical acquisitions up to the decision, including frames removed by input hooks. sensor_geometry retains recorded cameras when any selected representation keeps them. object_visibility covers the latest physical acquisitions independently of input hooks. detection_sensor names the detection source. detection_capture_id associates detections with its latest delivered frame across decisions. See metric evidence for how metrics use capture IDs.

    CaptureRecord records a timestamp's due sensor_ids, frame_ranges_us, raw and final model observations, physical state, viewpoints and object visibility. Frame ranges store each sensor's half-open exposure or scan interval. Negative IDs identify recorded warmup captures, numbered chronologically from -N to -1. A DeliveredAcquisition.capture_id of None means the acquisition was not produced by the scheduler. RunLog.captures and read_table(..., stream="captures") expose this stream separately from decisions.

    The model observation uses each frame's final payload, calibration and estimated pose from delivered(sensor_id) after localization and observation hooks. Owner-field edits apply to the latest frame in a sensor's delivery. Earlier frames retain their own processed values. Recording finalizes these inputs before stack reset or invocation. Frames that do not reach a finalized decision input, including terminal feedback and interrupted input processing, retain selected raw data and physical metadata without a model observation.

    The manifest stores format_version=2. Readers also accept version 1 logs without capture records. Sensor retention is applied per sensor acquisition. Both in-memory and read-back StepRecord delivery entries store metadata without their payloads. Capture records hold the selected acquisition payloads. Read them through RunLog.captures by capture_id. Geometry keys follow recording.sensor_ids order. Calibration mappings contain only sensors with a supplied calibration. Runner-recorded sensor payload arrays are read-only and may be shared between records. Pose and route snapshots are independent and writable. Recorder saves sensor payloads by reference, so callers must not modify them afterwards. Call Recorder.snapshot first when an independent copy is needed. When using Recorder directly, record captures before decisions that name their delivered_captures.

    Action requests and receipts distinguish requested changes from applied changes. A receipt's outcome is applied or not_applied, describing the action rather than its driving impact. Every receipt has a details mapping, empty when there is no detail. InsertionAttackAction adds rendered, reason, occlusion_source and ignored_occluders. InsertObject records object_id, asset_category, world_from_object and velocity. MoveObject records object_id and the interval's target world_from_object.

    StepRecord.object_visibility, the initialization event and RenderResult.object_visibility use object ID → camera name → ObjectVisibility. ObjectVisibility contains occlusion_source, ignored_occluders and visible_pixels.

    occlusion_source Visibility evidence
    depth Aligned scene depth
    actor_cuboids Actor box geometry
    scene_visibility Rendered probes used during composite insertion
    scene_render Objects rendered together with the scene

    See Simulators for visibility and composition.

    EventRecord captures initialization, termination and failure/cleanup information outside a decision. NuRec termination includes ground_contact_failures, counts by rejected ground-fit reason. A run ended by its terminate_when predicate records terminated_by_condition: true. RunLog.status distinguishes completed, failed, cancelled and incomplete runs.

    Parquet stores typed scalar and nested values. Large arrays occupy payload shards. Payloads publish before referring record parts. Completion metadata publishes last. A crash leaves published parts readable and may lose an open part. Readers ignore *.open files.

    SerializationRegistry handles JSON-compatible encoding and independent in-memory snapshots. Registered dataclasses reconstruct on read. Native values decode to ordinary data. Import and register user dataclasses before reading them. Missing registrations raise an error identifying the required registration. Framework registrations use type paths without eagerly importing SDKs.

    This self-contained example stores a user record in a temporary directory:

    from dataclasses import dataclass
from pathlib import Path
from tempfile import TemporaryDirectory

from avsectester.serialization import SerializationRegistry
from avsectester.runlog import Recorder, RunLog

@dataclass(frozen=True)
class CameraCheck:
    sensor: str
    visible_pixels: int

registry = SerializationRegistry()
registry.register_dataclass(CameraCheck)
with TemporaryDirectory() as directory:
    path = Path(directory) / "run"
    with Recorder(path, registry=registry) as recorder:
        recorder.record_event("camera_check", value=CameraCheck("front", 12))
    restored = RunLog.read(path, registry=registry)
    assert restored.events[0].data["value"] == CameraCheck("front", 12)

    Recorder supports bounded chunks and in-memory retention. Disabling in-memory retention requires a persistent output directory. Reader and recorder signatures are in the Python API.

    Failures and cleanup¶

    Unsupported environments are rejected during validation. Unsupported hook stages and command modes fail each run at its start, producing exit 1. A failing decision stops attack runtimes, records unapplied actions and cleans run resources. A requested action without an applied receipt is not evidence of an applied change. An incomplete log is not a completed run.
